# S6 — Review loop (20 min)

The compounding mechanism. Without it the OS is stale by week three and
they'll blame the concept.

## 1. Create learnings.md
Seed it with three entries from what already happened during the build.
Show the format: date, what was tried, what happened, what changes.

## 2. Install the append instruction
Add to AGENTS.md: "After any substantial task, propose one line for
learnings.md." This is the single highest-value line in the file.

## 3. The weekly review
Write playbooks/weekly-review.md: read the week's journal, decisions and
inbox; propose appends to learnings.md; flag context files contradicted by
recent work; list what to prune.

Where scheduling exists, create the scheduled task. Where it doesn't, have
them set a calendar reminder — same ritual, 15 minutes, fixed slot.
Keep the prune step human. An OS that files everything automatically stops
being one they read.

## 4. Run it once, now
On the material from this build. They must see the loop close.

## 5. The rot note
One short file: which layers age fast. Identity slowly. Playbooks medium.
Context when the role changes. Tool integrations whenever an API shifts.

## GATE
Ritual exists, is scheduled or reminder-set, and has been run once.

## Closing
Tell them plainly: 80% of this went up fast, the part that matters takes
weeks of real use. Four weeks of daily use plus a weekly prune beats any
amount of additional building. Resume phrase, one more time.
